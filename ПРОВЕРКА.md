# ПРОВЕРКА

> **GeraKProtocol · Контроль целостности документации**

Этот документ используется как практический чек-лист перед публикацией значимых изменений GeraKProtocol.

Цель проверки не в том, чтобы добавить бюрократию. Она нужна, чтобы карта экосистемы не расходилась сама с собой.

---

## 1. Структура

- [ ] Все основные документы находятся в корне репозитория.
- [ ] Визуальные материалы находятся в `ИЗОБРАЖЕНИЯ/`.
- [ ] Схемы находятся в `СХЕМЫ/`.
- [ ] Нет случайных дубликатов файлов.
- [ ] Новые документы имеют понятное назначение.

## 2. Проекты

- [ ] Названия репозиториев указаны точно.
- [ ] Ссылки на репозитории работают.
- [ ] Роли проектов актуальны.
- [ ] Статусы проектов актуальны.
- [ ] Новый проект добавлен только туда, где это действительно необходимо.

## 3. Связи

- [ ] Логические связи не названы техническими зависимостями.
- [ ] Функциональные связи описаны отдельно от принадлежности.
- [ ] Реальные технические зависимости не скрыты.
- [ ] GeraKProtocol не представлен как runtime dependency.

## 4. Документация

- [ ] README остаётся главной точкой входа.
- [ ] Внутренние ссылки ведут на существующие документы.
- [ ] Нет противоречий между `ПРОТОКОЛ.md`, `ЭКОСИСТЕМА.md`, `АРХИТЕКТУРА.md` и `ПРОЕКТЫ.md`.
- [ ] Термины соответствуют `ТЕРМИНОЛОГИЯ.md`.
- [ ] FAQ не содержит устаревших утверждений.
- [ ] CHANGELOG отражает значимые изменения.

## 5. Визуальная часть

- [ ] Mermaid-схемы отображаются корректно.
- [ ] SVG-схемы отображаются корректно.
- [ ] Подписи к схемам понятны без дополнительного контекста.
- [ ] Визуальные материалы не заменяют важный текст.
- [ ] Символ GeraKProtocol, если добавлен, соответствует `СТИЛЬ.md`.

## 6. Протокол

- [ ] Версия указана одинаково там, где она должна быть указана.
- [ ] Изменение соответствует MAJOR.MINOR.PATCH.
- [ ] Новое обязательное правило действительно необходимо.
- [ ] Рекомендация не превращена без причины в обязательное требование.
- [ ] Изменение не ограничивает самостоятельность проектов без необходимости.

## 7. README как первая точка входа

После проверки технических деталей README стоит открыть как обычный посетитель.

Человек должен быстро понять:

1. что такое GeraK;
2. что такое GeraKProtocol;
3. какие проекты существуют;
4. как они связаны;
5. почему связь не означает dependency;
6. куда перейти за подробностями.

Если для понимания этого приходится читать весь репозиторий, README нужно упростить.

---

## Когда проверка обязательна

Полный чек-лист рекомендуется использовать перед:

- выпуском новой версии протокола;
- добавлением нового проекта;
- изменением архитектурной модели;
- изменением обязательного правила;
- крупной перестройкой документации.

Для обычной опечатки достаточно исправить опечатку.

> **Проверяем не потому, что так положено. Проверяем, чтобы карта оставалась картой.**
